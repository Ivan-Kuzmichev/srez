# План реализации

Одиннадцать фаз. Каждая заканчивается работающим приложением, которое можно открыть и проверить. Порядок выбран так, чтобы ядро (журнал и расчёты) появилось раньше интеграций и чтобы диагностика была готова сразу после первой интеграции, где она нужнее всего.

Правила:

- Одна фаза — одна или несколько сессий. Фазы не смешивать.
- Экран считается готовым только в обеих раскладках, широкой и телефонной (определение в `CLAUDE.md`).
- В конце фазы: `pnpm check` проходит, критерии приёмки выполнены, `PROGRESS.md` обновлён.

## Фаза 0. Каркас

Цель: пустое приложение с правильной структурой, дизайн-системой и окружением.

Задачи:

1. Проект Next.js, TypeScript strict, pnpm, ESLint, Prettier, Vitest, Playwright, скрипт `pnpm check`.
2. Docker Compose: postgres, web, worker. Dockerfile с standalone-сборкой.
3. Drizzle: подключение, первая миграция, применение при старте.
4. Точка входа воркера с pg-boss, тестовая задача по расписанию.
5. Логгер pino с редактором секретов, идентификаторы запросов, запись в таблицу `logs`.
6. Токены оформления, шрифты через `next/font`, базовые компоненты из `08-ui.md`, раздел 3.
7. Каркас: боковое меню и нижняя панель, все маршруты из карты экранов как заглушки.
8. `lib/format.ts` с тестами, `domain/money.ts`.
9. `.env.example`, README по запуску.

Приёмка:

- `docker compose up` поднимает всё с нуля, главная открывается.
- Каркас совпадает с макетами `Main` и `MMain` по меню, панели, шрифтам и цветам.
- Страница-витрина `/dev/ui` показывает все базовые компоненты (убрать перед выпуском).
- Тестовая задача воркера пишет строку в `logs`.

## Фаза 4. Т-Инвестиции и сверка

Требования: FR-ONB-1…4, FR-SRC-1…4, 6, FR-REC-1…5. Спецификация: `05-integrations.md`, раздел 1.

Перед началом: проверить, отвечает ли API с машины разработки и с NAS. Если нет — настроить `TINVEST_PROXY_URL`.

Задачи:

1. Клиент Т-Инвестиций со схемами ответов, фикстурами и мок-сервером.
2. Шифрование секретов (`server/crypto.ts`), хранение токена.
3. Соответствие типов операций, импорт комиссий и налогов.
4. Задача `sync.tinvest`: первая загрузка окнами с прогрессом, дальнейшие с перекрытием.
5. Создание инструментов и догрузка истории цен. Цены бумаг из API.
6. Расписания выплат: купоны и дивиденды в `payout_events`.
7. Мастер первого запуска.
8. Экран источников: статус, счета, ручной запуск, замена токена, журнал синхронизаций. Статус в меню.
9. `domain/reconcile.ts`, задача сверки, таблицы `discrepancies`, `reconcile_exclusions`.
10. Экран разбора расхождений с исправлениями.

Приёмка:

- Повторный запуск синхронизации на тех же данных не создаёт ни одной операции.
- На мок-сервере мастер проходит все четыре шага, прогресс переживает перезагрузку страницы.
- Искусственное расхождение в фикстурах появляется на экране разбора, исправление его закрывает, отмена — возвращает.
- Токен в базе зашифрован, в логах и ответах его нет.
- Экраны совпадают с `Onboarding`, `Sources`, `Reconcile` и телефонными.
