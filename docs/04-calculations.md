# Расчёты

Все функции лежат в `src/domain`, принимают и возвращают `Decimal`, не ходят в базу и сеть. Каждый раздел заканчивается эталонными примерами: это обязательные юнит-тесты. Допуск сравнения, если не указан: 1e-6 относительный.

## 1. Позиции и стоимость

Операции счёта сортируются по `executed_at`, затем по `created_at`. Отменённые пропускаются. Группировка по ячейке `(account, instrument, tag)`, тег разрешается по правилам из `03-data-model.md`.

Количество:

- увеличивают: `buy`, `transfer_in`, `fx_buy`, `accrual`, `split` (на разницу);
- уменьшают: `sell`, `transfer_out`, `fx_sell`, `redemption`.

Кэш — тоже позиция: инструмент вида `currency`. Его количество меняют все операции с ненулевым `amount` в этой валюте.

Каждое увеличение открывает лот с `unit_cost`:

```
unit_cost = (quantity × price + accrued_interest + (deductFees ? fee : 0)) / quantity
```

Для `accrual` и `transfer_in` без цены `price` равна цене закрытия на дату операции.

Каждое уменьшение закрывает лоты по FIFO и пишет `lot_closures`:

```
proceeds = quantity × price − (deductFees ? fee : 0)
pnl      = proceeds − Σ(закрытое количество × unit_cost лота)
```

Позиция:

```
cost_basis = Σ(remaining × unit_cost) по открытым лотам
avg_price  = Σ(remaining × price покупки) / quantity      -- «чистая» средняя, без комиссий и НКД, для показа
value      = quantity × последняя цена
unrealized = value − cost_basis
```

У облигаций цена в операциях хранится в деньгах. Процент от номинала — только формат вывода.

**Эталон 1.1, акция.** Покупки: 500 × 251,00; 400 × 271,20; 200 × 284,45; 100 × 312,10. Комиссий нет. Цена сейчас 312,50.
Ожидается: количество 1 200; `cost_basis` 322 080; `avg_price` 268,40; `value` 375 000; `unrealized` +52 920 (+16,43 %).

**Эталон 1.2, с выплатами.** К 1.1 добавить дивиденды 17 000 и 37 400.
Ожидается: выплаты 54 400; полный результат +107 320; к вложенному +33,32 %.

**Эталон 1.3, дробное количество.** 0,0620 по 5 240 000, затем 0,0100 по 6 120 000.
Ожидается: количество 0,0720; `avg_price` 5 362 222,22 (округление до копеек на выводе).

**Эталон 1.4, FIFO.** Покупка 10 × 100, покупка 10 × 120, продажа 15 × 130.
Ожидается: закрыто 10 из первого лота и 5 из второго; `pnl` = 15 × 130 − (10 × 100 + 5 × 120) = 350; остаток 5 по 120.

## 2. Пересчёт валют

```
value_rub = value × курс(валюта → RUB, дата)
```

Курс берётся на дату операции или снимка. Если курса на дату нет, используется последний предыдущий. Отображение в долларах и евро — деление рублёвого ряда на курс соответствующей даты.

## 3. Внешние потоки

Область расчёта — набор ячеек `(account, tag)`: портфель или всё вместе. Внешний поток — операция, которая меняет стоимость области не за счёт рынка:

| Операция | Условие | Знак потока |
|---|---|---|
| `deposit`, `transfer_in` | Денежная или бумажная ячейка в области | + |
| `withdrawal`, `transfer_out` | То же | − |
| `buy` | Бумага в области, а деньги списаны с ячейки вне области | + на сумму сделки |
| `sell` | Бумага в области, деньги зачислены вне области | − |
| `dividend`, `coupon`, `interest` | Бумага в области, деньги зачислены вне области | − |
| `accrual` | Всегда | не поток |

Денежная ячейка счёта принадлежит тегу по умолчанию (`fin_accounts.default_tag_id`). Портфель с правилом `all` включает и её, поэтому для него потоки — только пополнения и выводы.

Поток области за день считается из операций по правилам таблицы, а не суммой по ячейкам: сделка внутри области потоком не является. Потоки не хранятся, они считаются на лету.

«Вложено» = сумма потоков с начала. «Прибыль» = стоимость − вложено.

Разложение прибыли на странице портфеля:

```
курсовая = unrealized + realized
выплаты  = dividend + coupon + interest за вычетом налога
прочее   = прибыль − курсовая − выплаты     -- комиссии, курсовые разницы по кэшу; показывать, только если ≠ 0
```

**Эталон 3.1.** Стоимость 4 812 360, потоки с начала 4 199 460. Прибыль 612 900, к вложенному +14,59 %.

## 4. XIRR

Потоки области с точки зрения инвестора: пополнение со знаком минус, вывод со знаком плюс, в конце плюс текущая стоимость. Решается уравнение

```
Σ CF_i / (1 + r)^((d_i − d_0) / 365) = 0
```

Метод Ньютона от 0,1, при расходимости — бисекция на [−0,99; 10]. Если потоков меньше двух или период короче суток, результат `null`, интерфейс показывает прочерк. Для периода короче года показывается годовое значение с пометкой.

**Эталон 4.1.** −100 000 на 2025-01-01, +110 000 на 2026-01-01. Ожидается 10,00 %.

**Эталон 4.2.** −1 000 на 2025-01-01, −1 000 на 2025-07-01, +2 150 на 2026-01-01. Ожидается 10,0527 %.

## 5. TWR

По дневным снимкам области. `V_t` — стоимость на конец дня, `F_t` — внешний поток за день (приток положительный):

```
r_t = (V_t − F_t) / V_{t−1} − 1
TWR = Π(1 + r_t) − 1
```

Если `V_{t−1} = 0`, день считается стартовым: `r_t = V_t / F_t − 1`.

Сравнение с бенчмарком: `TWR портфеля − (P_конец / P_начало − 1)` индекса за те же даты, в процентных пунктах.

**Эталон 5.1.** V = [100 000; 101 000; 151 500; 150 000], F = [0; 0; 50 000; 0]. Ожидается TWR 0,4950 %.

## 6. Изменение за день

```
Δ = V_сегодня − V_вчера − F_сегодня
Δ% = Δ / V_вчера
```

## 7. Структура и отклонения

Доля класса = стоимость позиций класса / стоимость области. Отклонение = доля − цель, в п.п. Предупреждение, если модуль отклонения больше порога портфеля.

**Эталон 7.1.** Стоимость 2 946 200. Классы: акции 1 130 600; облигации 570 600; фонды 387 400; крипта 613 100; кэш 244 500. Цели 40/25/15/15/5.
Ожидается: доли 38,4/19,4/13,1/20,8/8,3 %; отклонения −1,6/−5,6/−1,9/+5,8/+3,3 п.п.

## 8. Ребаланс

Вход: стоимости классов `v_c`, цели `t_c`, взнос `A`, режим, флаг «использовать кэш сверх цели».

```
V'       = Σ v_c + A
излишек  = max(0, v_cash − t_cash × V')
бюджет   = A + (флаг ? излишек : 0)
```

Режим «только докупать»:

```
дефицит_c = max(0, t_c × V' − v_c)          для всех классов, кроме кэша
покупка_c = бюджет × дефицит_c / Σ дефицит   но не больше дефицит_c
```

Суммы округляются до 100 ₽ методом наибольших остатков, чтобы итог равнялся бюджету. Остаток бюджета, если дефициты меньше, остаётся кэшем.

Режим «можно продавать»: `сделка_c = t_c × V' − v_c` для всех классов, отрицательная — продажа.

Подбор бумаг: для класса с покупкой берётся крупнейшая позиция этого класса в портфеле. Количество = сумма / (цена × лот), округлённое до ближайшего целого числа лотов.

**Эталон 8.1.** Данные из 7.1, взнос 150 000, только докупать, флаг выключен.
Ожидается: излишек кэша 89 690; покупки — облигации 78 600, акции 41 700, фонды 29 700; доли после 37,9/21,0/13,5/19,8/7,9 %; наибольшее отклонение было 5,8 п.п., стало 4,8.

**Эталон 8.2.** К 8.1: цены 634,00; 312,50; 7,45, лот 1.
Ожидается: 124, 133 и 3 987 штук.

## 9. Выплаты

- Получено: операции `dividend`, `coupon`, `interest` за период, за вычетом `tax`.
- Ожидается: события `payout_events` с датой выплаты после сегодня × количество в позиции (на дату отсечки, если она прошла, иначе текущее).
- Прогноз за год = получено с начала года + ожидается до конца года. Среднее в месяц = прогноз / 12.
- Свой актив с оценкой «процент годовых»: раз в месяц в день открытия создаётся операция `interest` на `стоимость × ставка / 12`.

**Эталон 9.1.** Получено 210 108, ожидается 69 860. Прогноз 279 968, в месяц 23 331 (округление до рубля).

**Эталон 9.2.** Вклад 210 000 под 16 %. Месячная выплата 2 800.

## 10. Начисления по крипте

Раз в сутки, в задаче ежедневного снимка, для каждого доходного токена на кошельке.

Токен с растущим балансом (`yieldKind: 'rebasing'`):

```
начисление = баланс_сегодня − баланс_вчера − поступления + списания
```

Токен-обёртка (`yieldKind: 'wrapped'`):

```
начисление в базовой монете = количество × (курс_сегодня − курс_вчера)
```

Положительное начисление записывается операцией `accrual` на этот день, оценивается по цене дня. Отрицательное (штраф, слэшинг) записывается как `other` с пояснением. Нулевое не записывается.

При подключении кошелька с историей создаётся одна запись «начислено до подключения»: текущий баланс минус все поступления плюс все списания.

Начисление не является внешним потоком. В журнале и на странице выплат показывается свёрнутым за месяц.

**Эталон 10.1.** Вчера 1 000,00, сегодня 1 000,14, переводов нет. Начисление 0,14.

**Эталон 10.2.** Вчера 1 000,00, днём поступило 500,00, сегодня 1 500,20. Начисление 0,20.

**Эталон 10.3.** Обёртка: количество 2,0, курс 1,1500 → 1,1502. Начисление 0,0004 базовой монеты.

## 11. Риск

По дневному ряду TWR области.

- Индекс стоимости: `I_0 = 1`, `I_t = I_{t−1} × (1 + r_t)`.
- Просадка: `DD_t = I_t / max(I_0..I_t) − 1`. Максимальная — минимум ряда. Восстановление — число дней от дна до возврата к прежнему максимуму.
- Волатильность: выборочное стандартное отклонение дневных доходностей × √252.
- Бета: `cov(r_портфель, r_бенчмарк) / var(r_бенчмарк)` по дням, где есть оба значения, за последний год.
- Худший месяц: минимальная доходность календарного месяца.
- Концентрация: доля каждой бумаги от стоимости области. Лимит «один эмитент» считается по полю `issuer`, если оно заполнено, иначе по бумаге.

**Эталон 11.1.** Стоимости [100; 110; 99; 104,5; 120], потоков нет.
Ожидается: максимальная просадка −10,00 % на третий день; восстановление на пятый; волатильность 170,7 % годовых.

## 12. Облигации

Потоки бумаги: будущие купоны и погашения номинала из `payout_events`. Грязная цена = чистая + НКД.

- Доходность к погашению: эффективная годовая, то же уравнение, что XIRR, где первый поток — минус грязная цена сегодня.
- Дюрация Маколея: `Σ(t_i × PV_i) / Σ PV_i`, время в годах. Модифицированная: `D / (1 + y)`.
- Для плавающего купона будущие выплаты берутся равными текущему купону, значение помечается как приблизительное.
- По области: средние, взвешенные по стоимости. Оценка при сдвиге ставки на Δ: `−D_мод × Δ × стоимость`.

**Эталон 12.1.** Номинал 1 000, купон 35,40 каждые 182 дня, осталось 30 выплат, чистая цена 634,00, НКД 0.
Ожидается: доходность 12,99 %; дюрация Маколея 7,95 года; модифицированная 7,04.

**Эталон 12.2.** Стоимости 646 680; 221 320; 217 760; 201 000. Доходности 12,8; 15,0; 12,9; 15,6 %. Дюрации 7,4; 0,1; 6,9; 6,2.
Ожидается: средняя доходность 13,63 %; дюрация 5,87; при росте ставки на 1 п.п. −75 563.

## 13. Прибыль за год

- Результат продаж: сумма `pnl` из `lot_closures` за год. В режиме «по средней» себестоимость продажи = количество × средняя цена позиции на момент продажи.
- Срок владения: от открытия лота до закрытия. Группы: меньше года, от года до трёх, больше трёх лет.
- Итог = результат продаж + выплаты − комиссии − налоги.

**Эталон 13.1.** Сделки: −1 200; +9 800; +4 200; −16 500; +4 450. Выплаты 210 108. Комиссии 2 316, налоги 24 180.
Ожидается: результат продаж +750 (прибыльные +18 450, убыточные −17 700); итог +184 362.

## 14. Сверка

Для каждой пары «счёт, инструмент», кроме исключённых: количество из `positions` против количества от брокера. Расхождение, если разница по модулю больше 1e-9.

Догадка о причине:

- брокер показывает больше, сделок после последней известной нет → `transfer`;
- инструмент — валюта → `fx`;
- облигация, дата погашения прошла, у брокера ноль → `redemption`;
- отношение количеств — целое число или обратное ему → `split`;
- иначе → `unknown`.

## 15. Точность вывода

Округление только при форматировании: деньги до рубля в сводках и до копеек в сделках, проценты до одного знака, количество крипты до значащих цифр без хвостовых нулей. Внутри расчётов округления нет.
