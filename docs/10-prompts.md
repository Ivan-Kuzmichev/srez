# Готовые запросы для Claude Code

Скопируй нужный блок в сессию. Запросы на русском, код и коммиты Claude Code пишет на английском (правило из `CLAUDE.md`).

## 1. Первая сессия

```
Прочитай CLAUDE.md, затем docs/01-requirements.md, docs/02-architecture.md,
docs/08-ui.md и docs/09-plan.md. Открой несколько макетов из design/screens,
как минимум Main.html, MMain.html, Portfolio.html и Operations.html.

Пока ничего не пиши. Сделай три вещи:
1. Перескажи в 10–15 строках, что мы строим и из чего.
2. Перечисли всё, что в документах противоречиво, неполно или устарело
   относительно текущих версий Next.js, Better Auth, Drizzle и pg-boss.
   Сверься с их актуальной документацией.
3. Предложи план фазы 0 по задачам, с командами и структурой файлов.

После моего подтверждения начинай фазу 0.
```

## 2. Начало очередной фазы

```
Начинаем фазу N из docs/09-plan.md. Прочитай её раздел, docs/PROGRESS.md
и документы, на которые фаза ссылается. Посмотри макеты экранов этой фазы.

Покажи план: задачи по порядку, какие файлы появятся, какие миграции,
какие тесты. Отдельно назови решения, которые ты принимаешь сам, и вопросы,
на которые нужен мой ответ. Код — после подтверждения.
```

## 3. Продолжение после перерыва

```
Прочитай docs/PROGRESS.md и git log за последние 20 коммитов.
Скажи, на какой задаче мы остановились и что осталось в фазе.
Продолжай со следующей задачи.
```

## 4. Закрытие фазы

```
Проверь фазу N по критериям приёмки из docs/09-plan.md. Для каждого критерия
напиши: выполнен или нет, и чем это подтверждается (тест, команда, экран).
Запусти pnpm check. Сравни готовые экраны с макетами на ширине 1440 и 390
и перечисли расхождения. Ничего не исправляй, пока я не посмотрю список.
```

## 5. Сверка экрана с макетом

```
Открой design/screens/<Имя>.html и реализацию маршрута <маршрут>.
Сравни по блокам сверху вниз: состав, порядок, отступы, размеры шрифта,
цвета, выравнивание чисел. Перечисли расхождения списком и исправь их.
Числа и названия в макете условные, их не переноси.
```

## 6. Ошибка

```
Проблема: <что вижу и что ожидал>.
Шаги: <как воспроизвести>.

Сначала найди причину: логи (таблица logs или /api/v1/logs), данные в базе,
код. Напиши, в чём причина и чем это подтверждается. Потом предложи
исправление и тест, который падал бы без него. Правь после моего согласия.
```

## 7. Новая идея по ходу работы

```
Запиши в docs/BACKLOG.md: <идея>. В текущую фазу не включай.
```

## Подсказки по работе

- Держи сессию в пределах одной фазы. Большую фазу (4, 6, 8) дели на две-три сессии по задачам.
- Проси план перед кодом и читай его: дешевле поправить план, чем переделывать.
- После фазы 5 выпусти API-токен. Тогда при разборе ошибок можно дать ассистенту доступ к логам вместо пересказа.
- Документация Claude Code: https://docs.claude.com/en/docs/claude-code/overview
