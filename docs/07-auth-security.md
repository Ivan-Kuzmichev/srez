# Вход и безопасность

Библиотека: Better Auth (https://www.better-auth.com/docs) с плагинами username, two-factor и passkey, адаптер Drizzle. Точные имена пакетов, импортов и опций сверить с документацией на момент реализации.

## 1. Пользователь

- Публичной регистрации нет. Эндпоинты регистрации Better Auth отключены.
- Первый пользователь: `pnpm cli user:create --username <имя>`, пароль запрашивается в терминале.
- Сброс: `pnpm cli user:reset-password --username <имя>`. Сбрасывает пароль, завершает все сессии. 2FA и пасскеи не трогает, для них отдельные флаги `--disable-2fa`, `--remove-passkeys`.
- Пароль: не короче 12 символов, хэш средствами библиотеки (argon2id или scrypt).

## 2. Вход по паролю

1. Логин и пароль.
2. Если включена 2FA и устройство не доверенное — экран кода.
3. Сессия.

- Ошибка не раскрывает, что именно неверно: «Неверный логин или пароль».
- Счётчик неудач по логину: после 5 подряд вход по паролю закрыт на 15 минут. Экран показывает оставшееся время. Успешный вход обнуляет счётчик.
- Отдельно ограничение по адресу: 20 попыток в минуту на любые эндпоинты входа.
- Неверный код 2FA: 5 попыток, затем возврат на экран пароля.

## 3. Двухфакторная защита

- TOTP, 6 цифр, шаг 30 секунд, допуск ±1 шаг.
- Подключение: показать QR и ключ, принять код, только после верного кода включить.
- После включения один раз показать 10 резервных кодов. Хранить зашифрованными секретом приложения (Better Auth проверяет коды расшифровкой, хэши он не поддерживает). Каждый код одноразовый.
- «Выпустить новые» аннулирует старые.
- Отключение требует пароль.

## 4. Пасскеи

- WebAuthn, обязательная проверка пользователя (`userVerification: 'required'`), обнаруживаемые учётные данные.
- Пасскей — полный вход: ни пароль, ни код после него не спрашиваются. Блокировка по паролю на него не действует.
- На экране входа поле логина имеет `autocomplete="username webauthn"`, браузер сам предлагает пасскей.
- Добавление и удаление — в настройках, у каждого пасскея имя устройства, дата добавления и последнего входа.

Пасскеи работают только в защищённом контексте и привязаны к домену из `APP_URL`. Открытие по IP-адресу или по HTTP делает их недоступными: в этом случае кнопки пасскея скрываются, а в настройках показывается объяснение. Смена домена делает старые пасскеи нерабочими.

## 5. Сессии

- Кука `httpOnly`, `secure`, `sameSite=lax`.
- Обычная сессия: кука до закрытия браузера и не дольше 24 часов, без продления (так устроен `rememberMe: false` в Better Auth). С «запомнить устройство» — 30 дней со скользящим продлением, и это же устройство не спрашивает код 2FA.
- В настройках список сессий: браузер и система, способ входа, адрес, последняя активность. Завершение одной и всех, кроме текущей.
- Смена пароля и отключение 2FA завершают все остальные сессии.

## 6. Защита запросов

- Все страницы группы `(app)` и все server actions проверяют сессию на сервере. Проверки только в middleware недостаточно.
- Server actions: встроенная проверка источника Next.js. Обработчики `/api/v1` принимают только Bearer-токен, куки игнорируют — CSRF к ним неприменим.
- Заголовки: `Content-Security-Policy` без `unsafe-inline` для скриптов, `X-Frame-Options: DENY`, `Referrer-Policy: same-origin`, `Strict-Transport-Security` при HTTPS.
- Все входные данные проверяются Zod.

## 7. Секреты в базе

Шифруются перед записью: токен Т-Инвестиций, токен Telegram-бота, ключ CoinGecko.

- AES-256-GCM, ключ из `APP_SECRET_KEY`, случайный nonce на каждое значение, формат `версия | nonce | шифртекст | тег`.
- Расшифровка только в воркере и только в момент запроса к внешнему API.
- В интерфейсе секрет после сохранения не показывается, только факт наличия и дата.
- Потеря `APP_SECRET_KEY` означает повторный ввод токенов. Это написано в README по развёртыванию.

## 8. API-токены

- Формат `inv_` + 32 случайных байта в base62. Показывается один раз при создании и перевыпуске.
- В базе sha-256 от токена и последние 4 символа для показа.
- Срок действия: 24 часа, 7 дней, 30 дней или без срока.
- Права и ограничение по сети — в `06-api.md`.

## 9. Логи и приватность

- Редактор секретов в логгере обязателен, см. `02-architecture.md`.
- События входа пишутся с логином, способом, адресом, результатом. Пароли и коды — никогда.
- Опция «скрывать суммы и количества» заменяет числа в сообщениях логов на `•••` на уровне логгера.

## 10. Проверки, которые должны быть в тестах

- Нельзя вызвать ни один server action без сессии.
- Блокировка срабатывает на пятой неудаче и снимается через 15 минут.
- Резервный код не срабатывает дважды.
- Токен с `local_only` отклоняется при внешнем адресе и при поддельном `X-Forwarded-For` от недоверенного источника.
- Отозванный и просроченный API-токен получают 401.
- В ответах API и в логах нет значений секретов из фикстур.
