### Фаза 1

Решения, согласованные с владельцем 2026-10-08:

| Решение | Причина |
|---|---|
| Резервные коды 2FA хранятся зашифрованными, не хэшами. `07`, раздел 3 поправлен | Better Auth сверяет коды расшифровкой |
| Сессия без «запомнить»: кука до закрытия браузера, не дольше 24 ч, без продления. `07`, раздел 5 поправлен | Поведение `rememberMe: false` в Better Auth |
| Email пользователя — заглушка `<логин>@local.invalid` | `user.email` обязателен в схеме Better Auth |
| Блокировка по логину своя: хук перед `/sign-in/username` + `login_attempts` | В Better Auth её нет |
| Поля `passkey.lastUsedAt`, `session.loginMethod`, `user.passwordChangedAt` через `additionalFields` | Их показывает макет `Security` |
| QR-код — пакет `uqr` | Согласовано |
| Лимит 20 запросов в минуту на вход, в памяти web | Один процесс |
| Заголовки безопасности и CSP — в фазе 10 | По плану |
| В разработке база по умолчанию `~/.srez/dev.db`, а не `./data` | Turbopack следит за всем деревом проекта и перезагружает страницу при каждой записи в файл базы. Это же было причиной нестабильных e2e на dev-сервере в фазе 0 |
| Перед QR добавлен шаг «Подтвердите паролем», которого нет в макете `Security` | `enableTwoFactor` в Better Auth требует пароль, а секрет создаётся только им. Подтвердить с владельцем |
| Подпись в приложении-аутентификаторе: `Srez: <логин>@local.invalid` | Better Auth подписывает запись email пользователя |
| `getSession()` собирает заголовок `cookie` из `cookies()`, а не из `headers()` | После включения или отключения 2FA Better Auth меняет сессию, и Next перерисовывает страницу в том же запросе со старым заголовком |
| Next проверяет типы по `tsconfig.build.json` без тестов | Тестов нет в контексте сборки Docker; `pnpm check` проверяет всё |
| compose передаёт переменные явно через `environment` с подстановкой из `.env` | `env_file` не передавал значения из оболочки |
| Порт web по умолчанию слушает только `127.0.0.1` (`SREZ_BIND`) | Без адреса сокета `X-Forwarded-For` подделывается при прямом доступе |

### Приёмка фазы 1

- Без сессии любой маршрут ведёт на вход (`proxy.ts` + `requireSession`, e2e `auth.spec.ts`), любой server action отвечает `UNAUTHORIZED` (`actions.test.ts` обходит все модули).

- Экраны `Login`, `LoginError`, `LoginLocked`, `TwoFactor`, `TwoFactorError`, `Passkey`, `Security`, `SecurityOn` сверены со скриншотами на 1440 и 390. Отличие от `Security` — шаг «Подтвердите паролем» перед QR (см. решения).

Найдено для фазы 5: standalone-сервер Next сам дописывает адрес сокета в `X-Forwarded-For` (в Docker без прокси пришло `172.19.0.1` без заголовка от клиента). Значит, крайний правый адрес — настоящий отправитель; проверить перед токенами `local_only`.
